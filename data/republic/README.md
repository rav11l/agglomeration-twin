# Двойник всей Республики Татарстан · версия 0.3.1

Подготовлено 26.11.2026. Охват: все 45 МО исходного двойника — 43 муниципальных района, Казань и Набережные Челны. Исходники и сжатый срез предназначены для Git, автономный HTML и полный реестр включаются в архив выпуска. Состояние внешней публикации проверяется отдельно.

Срез населения относится ко всему МО, включая входящие города и сёла. Отношение работников к населению не является долей работающих жителей. Новые муниципальные статусы и изменения границ после даты исходных слоёв отдельно не реконструируются.

## Где лежат исходные файлы

- `data/southeast/baseline_2024.csv`: ранее проверенный сопоставимый срез по всем 45 МО, включая ссылки на исходные выгрузки населения и зарплат.
- `data/districts_input.csv`: канонические ОКТМО и идентификаторы муниципалитетов.
- `data/osrm_minutes.csv`: направленная дорожная матрица.
- `data/agglomerations.json`: ядра и пояса.
- `data/eisgs_rt_under_construction_2026-10-27.csv`: исходные объекты ЕИСЖС.
- `data/republic/vacancies_2026-11-26.json`: полный региональный срез с аудитом запросов, без контактных полей.
- `data/republic/vacancy_pages_2026-11-26/` и `vacancy_supplements_2026-11-26/`: закреплённые производные ответы постраничной выдачи и уточняющих запросов по времени обновления.
- `data/republic/boundaries.json`: закреплённый полный слой муниципальной геометрии; поля расходов из исходной карты не перенесены.
- `data/republic/housing_overrides.json`: одна проверенная адресная привязка, со ссылкой на первоисточник.

## Сопоставление объектов и объявлений

Основная привязка жилья — точка координат ЕИСЖС к упрощённому полигону МО. Многоконтурные полигоны и отверстия обрабатываются по правилу even–odd. Если точка не попадает ни в один контур, используется однозначный адрес. Для объекта 73243 («Радужный-2», село Осиново, 171 квартира) сокращённого адреса и геометрии оказалось недостаточно: принадлежность к Зеленодольскому району проверена по официальному адресу администрации Осиновского сельского поселения — https://zelenodolsk.tatarstan.ru/rural_settlements/osinovo/ispolcom.htm. Исходные координаты не изменены. Это единственное явно закреплённое исключение; оно отражено в аудите.

Для вакансий используется адрес рабочего места. Явно указанный район или городской округ имеет приоритет над названием улицы. Название вакансии и юридический адрес работодателя для назначения муниципалитета не используются. Однозначно привязаны 10 302 объявления. В 10 записях не хватает адресных сведений для назначения МО, ещё в 89 указан более чем один муниципалитет. Эти 99 записей сохранены в `outputs/republic/vacancies_unassigned.json` и в полном CSV-реестре, но не размножаются по муниципальным профилям.

Получен весь региональный срез портала — 10 401 уникальная пара «работодатель + идентификатор вакансии», что совпадает с `meta.total` источника. Из 111 сохранённых ответов получено 10 463 строки; после устранения повторов осталось 10 401 объявление. Глубокая пагинация после первых 10 000 строк возвращает HTTP 500; хвост забран фильтром `modifiedTo`. Совпадающие даты обновления на границах страниц давали повторы и пропуски: шесть узких временных окон восстановили недостающие записи. API принимает UTC-время до секунд (`...Z`), но возвращает 500 для миллисекунд и смещения `+0300`; это закреплено в коллекторе.

Полнота относится к этому порталу, а не всему рынку труда Татарстана. К муниципалитетам привязаны 99,05% объявлений; 99 неоднозначных или неполных адресов остаются отдельно. Сферы объявлений не равны отраслевой структуре работающего населения. В выгрузку не переносятся поля телефонов, email, контактных лиц, резюме и полных описаний. ФИО индивидуальных предпринимателей в названии работодателя заменены общей меткой.

## Интерфейс и сценарии

Семь слоёв: население, работники без МСП, зарплата, работники на 100 жителей, жильё в снимке, пороговая доступность занятости, число привязанных объявлений портала. Фильтры: вся республика, первый и второй пояса трёх агломераций, территории вне этих поясов. Есть список 45 МО, поиск и сортировка таблицы, приблизительный масштаб выбранного района и раскрытие источников. Фильтр меняет отображение, но не исключает остальные МО из конкуренции в модели.

Доступность с конкуренцией: Wᵢⱼ = exp(−tᵢⱼ/τ), Sⱼ = ΣₖPₖWₖⱼ, Aᵢ = ΣⱼJⱼWᵢⱼ/Sⱼ. Дорожное время модели — среднее двух направлений, внутри МО — условно 10 минут. Пороговый слой карты требует доступности в обоих направлениях, поэтому использует максимум двух времён. Условная задержка применяется только к межрайонным связям.

Сценарий добавляет условные рабочие места в любые из 45 МО. Средний эффект взвешен по населению всех 45 МО, минимальный берётся по тем же территориям. «По численности жителей» распределяет ровно 1 000 мест методом наибольших остатков. «Выравнивать доступность» — жадная эвристика десяти шагов по 100 мест: сначала максимизируется наименьший относительный прирост, при равенстве — средний. Глобальный оптимум для 45 МО не заявляется.

Трудовые поездки не наблюдаются. Изменения зарплат, миграция, квалификационное соответствие, занятость МСП, расписания транспорта, стоимость создания мест и внешние центры за границами РТ не моделируются. Сохранение массы занятости — проверка арифметики, не эмпирическая валидация трудовых потоков.

## Пересчёт и проверки

Из корня репозитория:

```text
python scripts/build_republic.py
python scripts/test_republic.py
node scripts/test_republic_ui.cjs
python scripts/render_republic_overview.py
```

Сборка, таблица и тесты не требуют сети. Для PNG необходим matplotlib. Оформление совпадает с действующей страницей двойника: фон #FBFAF7, акцент #1D3C5C, Inter и Source Serif 4, ширина 1080 px, тонкие границы и карточки. Шрифты встроены в HTML, включая кириллицу; лицензии OFL сохранены. HTML включает все стили, данные и код, работает без сервера и внешних библиотек.

Результаты:

- `site/tatarstan_twin_2026-11-26.html`: интерактивный двойник всей республики.
- `site/tatarstan_overview_2026-11-26.png`: обзор из тех же данных, не снимок браузера.
- `outputs/republic/enrichment.json`: полный набор данных интерфейса.
- `outputs/republic/municipalities_enriched.csv`: таблица по 45 МО.
- `outputs/republic/vacancies_registry_2026-11-26.csv`: полный реестр всех 10 401 объявлений с результатом адресной привязки.
- `outputs/republic/vacancies_unassigned.json`: 99 объявлений с неполным или неоднозначным адресом.
- `outputs/republic/housing_assignment_audit.json`: привязка всех 314 объектов.
- `outputs/republic/validation.json`: итоги проверок данных.
- `outputs/republic/ui_math_validation.json`: проверки сценариев и формул JavaScript.
- `outputs/republic/input_hashes.json`: SHA-256 исходных файлов.

Проверяются точный муниципальный охват, отсутствие дублей ОКТМО, полнота геометрии, баланс всех объектов и квартир ЕИСЖС, одна подтверждённая адресная привязка, отсутствие подмены пропусков вакансий нулями, сохранение массы занятости при нескольких параметрах времени, совпадение расчётов Python/JavaScript и сохранение 1 000 мест в сценариях. Визуальная проверка браузером не выполнена: встроенный браузер заблокировал протокол file:// своей политикой доступа.

## Повторный сбор из открытого API

```text
node scripts/collect_republic_vacancies.mjs
```

Коллектор использует полный код региона 1600000000000, сохраняет каждую страницу отдельно, продолжает сбор из закреплённых страниц и проверяет число уникальных записей против объёма источника. Временные окна и хвост выдачи сохраняются отдельно; неполный результат не заменяет подтверждённый полный файл. `scripts/embed_twin_fonts.mjs` сохраняет открытые шрифты действующей страницы и их лицензии; для повторного пересчёта они уже входят в репозиторий.

## Хранение и встраивание

В Git полный исходный срез хранится как `vacancies_2026-11-26.json.gz` без потери полей и аудита. Сборщик автоматически читает JSON или gzip; контрольные суммы фиксируют именно использованный файл. `data/republic/sources.json` устраняет зависимость от результатов исторического пилота. Данные для сайта — `outputs/republic/enrichment.json.gz`. Блок `site/republic_embed.html` загружает их из неизменяемого коммита и проверяет SHA-256, сохраняя стили и идентификаторы внутри Shadow DOM. Автономный HTML работает без сервера.
